# ADR-RN-016: Genesis Proof 01 anchoring transactions and execution controls

- Status: Accepted (founder approval of PR #10 as implemented, RN-NET-03B2-A acceptance)
- Date: 2026-11-01
- Builds on: [ADR-RN-009](ADR-RN-009-anchor-payload-encoding.md), [ADR-RN-010](ADR-RN-010-xrpl-testnet-memo-anchoring.md), [ADR-RN-011](ADR-RN-011-sepolia-transaction-data-anchoring.md), [ADR-RN-012](ADR-RN-012-cross-chain-trust-boundaries.md)
- Design: [Genesis Proof 01 preflight](../genesis/genesis-proof-01-preflight.md), [authorization](../genesis/genesis-proof-01-authorization.md)

## Context

Genesis Proof 01 is the first real dual-chain anchor: one commitment, one XRPL Testnet
transaction and one Sepolia transaction. ADR-RN-010 and ADR-RN-011 define what an anchor *looks
like* to a verifier, and they accept many transactions. Signing a real transaction means fixing one
exact construction, its costs, and the controls around keys and broadcasting. All of these are
irreversible once a transaction is public.

This ADR changes no format: the payload, the observation, the record and the report stay as they
are.

## Decision

1. **The XRPL transaction.** An unsigned `AccountSet` with exactly these fields:
   - `TransactionType`, `Account`, `Fee`, `Sequence`, `LastLedgerSequence` and `Memos`, plus
     `SigningPubKey` at signing time;
   - `Memos` holding exactly one anchor memo (`MemoType` = hex(`rnnet.anchor-payload.v1`),
     `MemoData` = the payload, no `MemoFormat`);
   - no `NetworkID` (Testnet's ID is 1), no `Flags` (or 0) and no settings fields.

   Other details:
   - **Fee:** 12 drops, with a hard cap of 1,000.
   - **Expiry:** `LastLedgerSequence` is required, set to the latest validated ledger + 20.
   - **Key:** an Ed25519 key.
2. **The Sepolia transaction.** An unsigned EIP-1559 (type `0x2`) transaction with:
   - chain ID `0xaa36a7`;
   - value 0 and an empty access list;
   - `input` exactly the 42-byte payload;
   - **sent to its own sender (a self-send).**

   Gas and fees:
   - **Gas limit:** 30,000. The intrinsic cost under Prague rules is 22,680. Unused gas costs
     nothing.
   - **maxFeePerGas:** 2 × the base fee + tip, never above 20 gwei.
   - **Priority fee:** 1 gwei.

   **Why a self-send.** A self-send involves no third-party address. The recipient is an account
   with no code, so nothing executes, and the sender is the only address involved. As in
   ADR-RN-012, the submitter stays a `CLAIMED` value.
   The sender must be a fresh key with no EIP-7702 delegation, so that it still has no code.
3. **The checks are executable.** The construction is pinned as code in
   `tools/genesis/prepare.mjs`:
   - `checkXrplAnchorTx` and `checkSepoliaAnchorTx` refuse every other construction;
   - an unbound template fails them.

   A transaction may be signed only if its check returns no problems. The checks accept only
   plain JSON data, and what is signed must be exactly the canonical JSON of the object that was
   checked.
4. **Separate decisions for keys, funding, signing and broadcasting.** Each step that touches a
   key, an account, funds or a network write needs its own founder decision (gates B–F of the
   authorization document). No approval carries over to another step or another network.
5. **Key hygiene.**
   - **New keys only.** Keys are new and single-purpose: one per network, testnet only.
   - **Generation.** Keys are generated by reviewed RN-NET code inside a network namespace.
   - **Storage.** Keys are never stored in a repository or worktree.
   - **No reuse.** Keys are never reused, and never derived from material any other project
     uses. This includes Frontera and Soberanía credentials, accounts and wallets.
   - **Signing and broadcasting stay apart.** Signing happens offline. Broadcasting is done by a
     process that never holds a key.

## Consequences

- **Small, fixed costs.** At most 1,000 drops on XRPL. On Sepolia, at most 30,000 × 20 gwei =
  0.0006 ETH. Expected costs are much lower (see the preflight document).
- **Tooling RN-NET-03B2-B must add:**
  - signing;
  - a write path (`submit`, `eth_sendRawTransaction`);
  - a few read-only methods: XRPL `account_info`; Ethereum `eth_getTransactionCount`,
    `eth_estimateGas`, `eth_getBalance` and `eth_getCode`.

  Each needs review, and the write path needs its own ADR. `packages/chain-readonly` stays
  read-only.
- **Open decision for RN-NET-03B2-B: the Sepolia signer dependency.** Node.js built-ins have no
  Keccak-256, and `crypto.sign` always hashes its input, so they cannot produce a recoverable
  secp256k1 signature over a Keccak-256 digest. RN-NET-03B2-B must choose, in its own ADR:
  - an audited third-party library, pinned like the existing development dependency;
  - or an original implementation, checked against published test vectors.

  Accepting this ADR does not make that choice. The XRPL signer needs no new dependency.
- **What this acceptance covers.** It accepts the construction and controls above. It does not
  accept ADR-RN-009 to ADR-RN-012, which remain Proposed, and it authorizes no gate beyond A.
- **Gas rules can change.** A later Ethereum fork may reprice calldata. Gas use must be confirmed
  with `eth_estimateGas` before signing, and the 30,000 limit re-checked.
- **What the anchor shows.** As ADR-RN-012 allows, the anchors show the same commitment payload
  in the data reported for both networks. They say nothing about whether the synthetic evidence is
  true. `CHAIN_PROVEN` is still never produced.
